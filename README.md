# Interpretable intrinsic dimension estimation through componentwise calibration of distance and angle

Code, reference data, and processed results for the manuscript of the same
title (Huang, Chen, and Chung; submitted to *Pattern Recognition*, 2026). The
Python package is named `danco`.

The estimator builds on DANCo (Ceruti et al., 2014): the intrinsic dimension
(ID) of a point cloud is the candidate dimension whose calibrated reference
statistics best match the observed nearest-neighbor distance ratios (distance
component) and the angles between neighbor displacements (angular component).
The paper keeps the two components separate so that a reference mismatch in one
component does not obscure informative evidence in the other, and evaluates four
statistical objectives:

| Paper name | Distance component | Angular component |
| --- | --- | --- |
| MiND--Full | MiND | full von Mises KL |
| MiND--Profiled | MiND | mean-direction-profiled von Mises KL |
| Gride--Full | generic-order Gride | full von Mises KL |
| Gride--Profiled | generic-order Gride | mean-direction-profiled von Mises KL |

Three documents describe the repository:

- this file: installation, data, the estimator API, how to reproduce each
  result, and the repository layout;
- [`experiments/README.md`](experiments/README.md): every experiment script
  with its options, seeds, and output files;
- [`results/REPRODUCTION_STATUS.md`](results/REPRODUCTION_STATUS.md): which
  archived result file and which generated table or figure stand behind each
  number in the paper, and which archived files the paper does not use.

## Install

Python 3.12 is required (`requires-python = ">=3.12,<3.13"`).

```bash
conda create -n danco python=3.12
conda activate danco
```

Then choose one route.

**Route A: the recorded CUDA 12.6 environment** behind the archived results
(`requirements-lock.txt` is a `pip freeze` of that environment, including
`torch==2.13.0+cu126`):

```bash
python -m pip install --extra-index-url https://download.pytorch.org/whl/cu126 \
    -r requirements-lock.txt
python -m pip install -e .
```

**Route B: CPU only.** Every experiment can run on the CPU; for the CNN
profiles replace `--backend gpu` with `--backend cpu` in the command below
(much slower; the GPU backend raises without CUDA rather than falling back).

```bash
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[dev,data]"
```

Optional extras: `data` and `gpu` both mean `torch` + `torchvision` (needed only
for the image and CNN experiments); `dev` adds `pytest` and `mpmath` (tests).
Route B is a supported configuration, not the exact recorded environment;
results may differ at floating-point precision.

The archived release is deposited at Zenodo under DOI
[`10.5281/zenodo.22970216`](https://doi.org/10.5281/zenodo.22970216) (see [Citation](#citation)).
The preprint is [arXiv:2609.37114](https://arxiv.org/abs/2609.37114), and the source
repository is <https://github.com/phonchi/componentwise-danco>.

## Data

`data/` is not part of the repository. The synthetic benchmark manifolds and the Gaussian
scale mixtures are generated by the scripts (scikit-dimension
`BenchmarkManifolds` and NumPy); nothing else is needed for the clean
benchmark, noise, GSM, sensitivity, runtime, and mechanism experiments.

### MNIST and CIFAR-10 (automatic)

`run_images.py`, `run_angle_diagnostics.py`, `run_class_survey.py`, and
`run_vm_adequacy.py` call `torchvision.datasets.MNIST` / `CIFAR10` with
`download=True` and `root="data"`. The first run downloads the files into
`data/MNIST/raw/` and `data/cifar-10-batches-py/`. The paper uses the MNIST
*test* split (digits 3 and 7, all 1010 and 1028 images) and the CIFAR-10
*train* split (classes 2 and 3, all 5000 training images of each; the class
survey uses all ten classes). The downloads are about 240 MB in total.

### Pretrained CNN weights (automatic)

`run_cnn_layers.py` loads `torchvision.models.{alexnet,vgg16,resnet18,resnet34}`
with their `DEFAULT` ImageNet weights. torchvision downloads them on first use
into the torch cache (`~/.cache/torch/hub/checkpoints/`, or `$TORCH_HOME`).

## API

### Quick start

```python
import numpy as np
from danco import DANCo

rng = np.random.default_rng(0)
X = np.zeros((1000, 50))
X[:, :20] = rng.normal(size=(1000, 20))   # a 20-dimensional Gaussian in D = 50

estimator = DANCo(N=X.shape[0], k=10, random_state=0, version="DANCo")
dimension, stats = estimator.evaluate(X, maxDim=50)
print(dimension, stats["objective"], stats["angle_status"])
# -> 19.999 full ok        (rounded; about 8 s on a laptop CPU)

both = DANCo(N=X.shape[0], k=10, random_state=0, version="DANCo").evaluate_all(X, maxDim=50)
print(both["de_standard"], both["de_nustrip"])
# -> 19.999 20.004         (MiND--Full and MiND--Profiled from one pass)
```

`X` must have exactly `N` rows: `N` is also the size of every calibration
hyperball, so it is fixed at construction and checked in `evaluate`.

### The four objectives

`version` names the objective that `evaluate` returns. The four basic
versions calibrate against Monte Carlo references drawn at the observed
sample size; **every experiment in the paper except the CNN profiles uses
these four**:

| Distance statistic | Full angular KL | Profiled angular KL |
| --- | --- | --- |
| MiND (`r_1 / r_(k+1)`) | `version="DANCo"` (MiND--Full) | `version="DANCo_nustrip"` (MiND--Profiled) |
| Gride (`r_(k/2) / r_k`) | `version="DANCo_gride"` (Gride--Full) | `version="DANCo_gride_nustrip"` (Gride--Profiled) |

Full and Profiled share the neighbor search, the angle statistics, and the
distance calibration and differ only in the angular discrepancy applied at
each candidate, so `evaluate_all` computes both objectives of one distance
statistic in a single pass (the second angular curve costs about two percent
of an evaluation). MiND and Gride are separate runs: they estimate different
distance ratios, so their reference sequences differ.

### Reference type: Monte Carlo (basic) or spline (`_fast`)

A basic version calibrates every candidate dimension `m = 1..maxDim` by
drawing one uniform hyperball of `N` points in `m` dimensions and computing
its `(dhat, nu, tau)` (the calibration cache; see `calibration_seeding` and
`calibration_data` below). Appending `_fast` to any basic version replaces
that sampling by a lookup in a precomputed spline surface of the same distance
statistic:

| Basic version (Monte Carlo) | Spline version | Objective |
| --- | --- | --- |
| `DANCo` | `DANCo_fast` | MiND--Full |
| `DANCo_nustrip` | `DANCo_nustrip_fast` | MiND--Profiled |
| `DANCo_gride` | `DANCo_gride_fast` | Gride--Full |
| `DANCo_gride_nustrip` | `DANCo_gride_nustrip_fast` | Gride--Profiled |

The packaged surfaces cover `N` in `[450, 700]` and candidates `1..400` at
`k = 10` (see [Spline surfaces](#spline-surfaces)). The CNN experiment runs
`version="DANCo_gride_fast"` through `evaluate_all` and reports the
Gride--Profiled value (the archived run metadata records that version string);
`DANCo_gride_nustrip_fast` returns the same number directly.

### Constructor

`DANCo(N=2500, k=10, calibration_data=None, fractal=True, verbose=False, random_state=None, version="DANCo", backend="cpu", backend_options=None, use_legacy_bessel=False, check_spline_range=True, calibration_seeding="stream")`

| Parameter | Default | Meaning |
| --- | --- | --- |
| `N` | `2500` | Number of points in `X` and in each calibration hyperball. |
| `k` | `10` | Neighborhood size. MiND uses the ratio `r_1 / r_(k+1)`; Gride uses the orders `n2 = k` rounded up to an even number and `n1 = n2 / 2` (5 and 10 for `k=10`, 3 and 6 for `k=5`). |
| `calibration_data` | `None` | A previously grown calibration cache (`stats["calibration_statistic"]` or `estimator.calibration_statistic` of another estimator with the same `N`, `k`, and distance statistic) to reuse and extend in place. The cache carries no RNG state: candidates already in it are reused exactly, but candidates added by the new estimator come from its own stream and differ from what the original estimator would have added. |
| `fractal` | `True` | Refine the integer argmin of the KL curve by interpolation (`scipy.optimize.minimize` on an interpolant of the curve: cubic for `maxDim > 3`, quadratic for 3, linear for 2; bounded to `[1, maxDim]`); `False` returns the integer candidate. |
| `verbose` | `False` | Print progress. |
| `random_state` | `None` | Seed of the calibration sampler (int, `RandomState`, or `None`). |
| `version` | `"DANCo"` | Objective and reference type; see the two tables above. |
| `backend` | `"cpu"` | `"cpu"` (scikit-learn kNN + numba angle kernel) or `"gpu"` (PyTorch, CUDA required). Applies to the observed-data statistics only; Monte Carlo calibration always runs on the CPU. |
| `backend_options` | `None` | Dict forwarded to the backend. `cpu` accepts none. `gpu` accepts `query_batch=128`, `angle_batch=4`, `dup_threshold=None`, `extra_neighbors=1`, `device=None` (`"cuda"`), `dtype="float32"`. |
| `use_legacy_bessel` | `False` | Evaluate the Full angular KL with unscaled Bessel functions (overflows for concentrations above about 709.78; the Profiled curve is unaffected). Kept for comparison, not for new results. |
| `check_spline_range` | `True` | For the `_fast` versions, raise instead of extrapolating when `N` or a candidate lies outside the fitted spline grid. |
| `calibration_seeding` | `"stream"` | `"stream"`: candidate `m` consumes the `m`-th draw of one RNG stream. `"derived"`: each candidate is seeded from `(random_state, N, m)`; it requires an integer `random_state` (checked at construction for every version) and has no effect on the `_fast` versions. |

Do not reassign `N`, `k`, `version`, or `backend` on an instance (the
distance strategy and backend are built at construction); create a new
estimator instead.

### `evaluate` and `evaluate_all`

`dimension, stats = estimator.evaluate(X, maxDim=100, n_jobs=1, spline_file=None)`
computes only the objective named by `version`.

`stats = estimator.evaluate_all(X, maxDim=100, n_jobs=1, spline_file=None)`
computes Full and Profiled of the same distance statistic in one pass.

- `X`: array of shape `(N, D)` with `D >= 2`.
- `maxDim`: largest candidate dimension; capped at `D`.
- `n_jobs`: threads for the CPU neighbor search.
- `spline_file`: alternative spline pickle for the `_fast` versions (default: the packaged surface of the distance statistic).

| Key | In | Content |
| --- | --- | --- |
| `dhat` | both | Distance-only estimate (continuous MLE of the MiND or Gride ratio law). |
| `mu_nu`, `mu_tau` | both | Mean von Mises location (radians) and concentration of the observed pairwise angles. |
| `angle_valid`, `angle_status` | both | Whether the angular component is available; `angle_status` is `"ok"`, `"distance_below_threshold"` (`dhat <= 5`), or `"zero_resultant"`. |
| `calibration_statistic` | both | The calibration cache (a live reference, not a copy; Monte Carlo statistics or spline lookups). Absent on the shortcut below. |
| `objective` | `evaluate` | `"full"` or `"profiled"`. |
| `estimate` | `evaluate` | The returned `dimension`: argmin over candidates of distance KL + this objective's angular KL, refined if `fractal`. |
| `kl_distance`, `kl_angle` | `evaluate` | Arrays `(maxDim,)`: the distance KL and this objective's angular KL per candidate. |
| `de_standard`, `de_nustrip` | `evaluate_all` | The Full and the Profiled estimate. |
| `kl_divergence` | `evaluate_all` | Array `(maxDim, 2)`: distance KL and Full angular KL per candidate. |
| `kl_ang_strip` | `evaluate_all` | Array `(maxDim,)`: Profiled angular KL per candidate. |

When `dhat <= 5` or the angular statistic is invalid, both methods return
`dhat` as the estimate(s), set the KL entries to `None`, and leave the
calibration cache untouched.

### Spline surfaces

**What a surface is.** For one distance statistic (MiND or Gride) a surface
stores the calibration statistics `(dhat, nu, tau)` as three smooth functions
of the candidate dimension `d` and the sample size `N`, so that a `_fast`
version can look them up instead of sampling hyperballs. One surface serves
both objectives of its distance statistic. The two packaged surfaces
(`src/danco/assets/fastdanco_splines_gride_400.pkl` for Gride,
`fastdanco_splines_400.pkl` for MiND) were generated by
`experiments/train_splines.py` with its default grid:

1. Grid: `d = 1..400` and `N in {450, 500, 580, 640, 700}` at `k = 10`
   (2000 cells).
2. For each cell, 35 uniform hyperballs of `N` points in `d` dimensions are
   drawn with `skdim.datasets.hyperBall`; replica `r` of every cell uses
   `random_state = seed + r` (`seed = 42`), so all cells share one sequence of
   balls.
3. Each ball is passed to `DANCo(k=10, N=N, version=<basic version>).danco_statistic`,
   which returns its `dhat`, `mu_nu`, and `mu_tau`; the cell keeps the mean of
   `dhat` and `mu_tau` and the circular mean of `mu_nu` (70,000 calibration
   runs in total, several hours).
4. Three `scipy.interpolate.RectBivariateSpline` surfaces (cubic in `d` and
   in `N` when the grid allows, lower order otherwise) are fitted to the
   `(d, N)` tables of `dhat`, `mu_nu`, and `mu_tau`; a validation report prints
   the mean and maximum relative error at the training points.
5. The pickle stores `k`, `d_range`, `N_range`, `spline_dhat`,
   `spline_mu_nu`, `spline_mu_tau`, plus `variant` (`"mind"` or `"gride"`) and
   `seed`. The packaged Gride surface carries `seed = 42`; the packaged MiND
   surface predates the seed stamp and cannot be reproduced bit for bit.

At evaluation time `danco.spline.spline_statistic` evaluates the three
surfaces at `(m, N)` for every candidate `m`, which replaces the hyperball of
the Monte Carlo path. With `check_spline_range=True` (default) the `_fast`
versions refuse `N` outside `[min(N_range), max(N_range)]` and candidates
above `max(d_range)` instead of extrapolating.

**Training your own surface.** The paper's grid takes several hours; this
demonstration grid takes about ten seconds:

```bash
python experiments/train_splines.py --variant gride \
    --d-max 30 --n-range 450,500 --replicas 5 --seed 1 \
    --output results/splines/demo_gride.pkl --yes
```

Options: `--variant {mind,gride}` (one surface per distance statistic),
`--d-min`/`--d-max` (candidate grid, default `1`/`400`), `--n-range`
(comma-separated sample sizes, default `450,500,580,640,700`), `--k`
(default `10`), `--replicas` (hyperballs per cell, default `35`), `--seed`
(default `42`), `--output` (default `results/splines/fastdanco_splines[_gride]_400.pkl`,
a directory that is not part of the repository), `--no-validate` (skip the
fit report), and `--yes` (without it the script only prints the job size).
The script prints the validation report (all three surfaces below 0.01%
relative error on the demonstration grid) and stamps `variant` and `seed`
into the pickle.

**Using a surface.** Pass the file to `evaluate` or `evaluate_all`; the
estimator's distance statistic and `k` must match the surface (checked at
load), `N` must lie inside the surface's `N` range, and `maxDim` must not
exceed its `d` range:

```python
Y = np.zeros((500, 20))
Y[:, :12] = np.random.default_rng(1).normal(size=(500, 12))   # 12-dimensional, D = 20

est = DANCo(N=500, k=10, version="DANCo_gride_nustrip_fast")
dimension, stats = est.evaluate(Y, maxDim=30, spline_file="results/splines/demo_gride.pkl")
print(dimension, stats["objective"])
# -> 12.990 profiled       (0.04 s: no sampling)
```

Requesting `N=1000` on this surface raises
`ValueError: DANCo_gride_fast: N=1000 is outside the range the splines were fitted on ([450, 500]) ...`,
and a MiND version raises because the file stores `'gride'` statistics.

## Reproducing the paper

Run every command from the repository root in the `danco` environment. The
scripts write CSV/NPZ files under `results/`; the tables and figures are then
generated from those files (next section).

The archived result files sit at the scripts' default output paths, and the
long-running scripts (`run_baselines.py`, `run_impl_comparison.py`,
`run_fusion_ablation.py`, `run_sensitivity.py`, `run_cnn_layers.py`) resume
from an existing output file, so rerunning a documented command as is only
reports the archived rows. To recompute, either pass `--no-resume` (where
available; this overwrites the archived file) or write to a new path with
`--output`/`--outdir` and compare. The table and figure generators always
read the archived paths under `results/`. Approximate cost on one workstation:
the clean benchmark about 14 CPU-hours of estimator time, each CNN replicate
about 25 minutes on one GPU, the other scripts minutes to a few hours. Options, seeds, and the exact files
each script writes are documented in [`experiments/README.md`](experiments/README.md);
the values the paper quotes from each file are listed in
[`results/REPRODUCTION_STATUS.md`](results/REPRODUCTION_STATUS.md).

## Tables and figures

```bash
python experiments/make_tables.py
python experiments/export_reference_curvature.py   # Table S1 CNN row
python experiments/make_figures.py
python experiments/make_graphical_abstract.py
```

By default everything the generators produce is written under
`results/generated/` (`tables/`, `figures/`, `graphical_abstract/`; not part
of the repository); `export_reference_curvature.py` additionally rewrites its
own result CSV under `results/diagnostics/`. To write the tables and figures
that the manuscript includes directly into a manuscript tree, add
`--paper-dir <dir>` to each command; they then go to `<dir>/tables` and
`<dir>/figures`, while outputs the manuscript does not include
(`table_impl.tex`, `fig_kl_diagnosis_main.pdf`, the editable SVG of the
graphical abstract) stay under `results/generated/`. The manuscript sources
themselves are not part of this repository. A table or figure whose source
file is missing is skipped with a message; a source file with unexpected
content (wrong replicate count, missing columns) raises an error.

## Tests

```bash
python -m pytest -q
```

169 tests: numerical kernels, backend agreement, calibration reuse, the Gride
closed-form KL against the archived quadrature, the experiment protocols
(seeds, deduplication, runtime stages), and the result contracts of the archived
CSV files. Without CUDA the GPU tests skip (14 skips without CUDA and torch), and the
suite finishes in under a minute.
